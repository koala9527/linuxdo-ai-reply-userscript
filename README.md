# Linux.do 有一说一 · 回帖助手

一个 linux.do 帖子页的油猴（Tampermonkey / Violentmonkey）脚本。

进入帖子详情页后，脚本自动把**当前页的标题 + 本页楼层内容**交给本地「有一说一」服务（`reply-assistant`）生成一条贴题的回复；有结果时右下角按钮变色，点开即可查看、一键复制。

脚本本身不再直接调用任何大模型接口，也不再内置提示词模板——所有生成能力都来自 `reply-assistant` 的 `POST /api/v1/say-one`。

## 使用边界

linux.do 明令禁止使用 AI 直接回复或润色回复。本项目只负责**生成候选文案并复制到剪贴板**，不会自动填写、自动发送，也不会改动站内输入框。是否使用、如何使用由你自己判断，因使用本项目导致的后果自负。

## 工作流程

1. 识别当前页面是否为帖子详情页（`/t/...`）。
2. 采集页面上的：
   - 帖子标题（`#topic-title h1` → 吸顶的 `h1.header-title` → `document.title` 依次兜底）
   - 本页已渲染的每一楼（`article[data-post-id]` 里的 `.cooked` 正文、作者名、楼层号）
3. 组装成一段对话文本：

   ```text
   帖子标题：……

   【楼主】……

   【本页回复】
   用户名：……
   用户名：……
   ```

   超过上限（默认 1900 字符，接口硬上限 2000）时按「回复从后往前裁 → 再裁楼主正文」的顺序截断。
4. `POST {服务地址}/api/v1/say-one`，`{ text, tone }`。
5. 结果回来后右下角按钮变绿并显示红点，点开面板查看。

生成一次通常需要 35–70 秒，期间按钮显示 `生成中 Ns`。

## 界面

右下角悬浮按钮有四种状态：

| 状态 | 颜色 | 文案 | 含义 |
| --- | --- | --- | --- |
| 待命 | 灰 | 有一说一 | 已进入帖子页，尚未开始 / 手动模式 |
| 生成中 | 蓝 | 生成中 12s | 正在请求服务 |
| 有结果 | 绿 | 看回复 | 结果就绪，点击打开面板 |
| 失败 | 红 | 生成失败 | 请求失败，面板里有原因和重试 |

面板内容：

- **回复正文**：主体内容，可直接选中
- **复制回复**：复制到剪贴板
- **重新生成**：用当前页面内容再生成一次
- **判断 / 共同看法 / 说明**：服务返回的 `key_point`、`global_pattern`、`caveat`
- **过程与依据**（折叠）：置信度、检索规模、耗时、参考的相似讨论
- **输入预览**（折叠）：实际发给服务的完整文本，便于核对
- **设置**（折叠）：服务地址、语气、自动生成开关、发送内容上限

## 安装

1. 浏览器安装 Tampermonkey 或 Violentmonkey。
2. 打开 `https://raw.githubusercontent.com/koala9527/linuxdo-ai-reply-userscript/main/linuxdo-ai-reply.user.js` 安装；或新建脚本后粘贴 `linuxdo-ai-reply.user.js` 内容保存。
3. 启动本地服务（见下），打开任意 `https://linux.do/t/...` 帖子页。

## 前置：启动「有一说一」

脚本默认请求 `http://127.0.0.1:8011`，即 `reply-assistant` 项目：

```powershell
cd C:\Code\reply-assistant
python run_one.py
```

确认服务可用：

```bash
curl http://127.0.0.1:8011/api/health
```

返回 `"ok": true` 且 `indexed_topics` 大于 0 即可。服务部署在别的机器上时，在面板「设置 → 服务地址」里改成对应地址即可（脚本通过 `GM_xmlhttpRequest` 发请求，不受 CORS 限制）。

## 设置项

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 服务地址 | `http://127.0.0.1:8011` | 修改后清空结果缓存 |
| 语气 | 直接 | `direct` 直接 / `calm` 平和 / `sharp` 犀利，对应接口 `tone` |
| 进入帖子页自动生成 | 开 | 关闭后只在点开面板后手动生成 |
| 发送内容上限 | 1900 | 200–2000，接口硬上限 2000 |

## 缓存与去重

- 结果按「帖子 id + 页码」缓存在浏览器里，有效期 24 小时，最多 30 条；再次进入同一页直接显示，不会重新等几十秒。
- 同一帖子 20 秒内不会重复自动请求。
- 帖子内滚动、点击楼层锚点导致的 URL 变化**不会**触发重新生成；只有换帖子或切换分页（`?page=`）才会。
- 生成中切到另一个帖子，新帖子会正常发起请求，旧请求的结果会被丢弃。

## 常见问题

**按钮一直灰色 / 显示生成失败**

面板里会写明原因。常见是服务没启动，或端口不是 8011。

**提示「没有读到帖子内容」**

页面楼层还没渲染出来。脚本最多等 12 秒，超时后刷新页面即可。

**输入预览里内容被截断**

正常。接口限制 2000 字符，脚本按上限裁剪，优先保留标题、楼主正文和靠前的回复。

**生成的回复不对味**

换「语气」再点「重新生成」。生成质量取决于服务端的检索与模型。

## 文件

- `linuxdo-ai-reply.user.js`：油猴脚本本体
- `scripts/validate.mjs`：本地静态校验

## 本地校验

```bash
node --check linuxdo-ai-reply.user.js
node scripts/validate.mjs
```

`validate.mjs` 除了检查必需函数与选择器，还会检查旧版直连 OpenAI 兼容接口、提示词模板等代码是否已彻底移除。
